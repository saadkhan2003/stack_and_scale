# 15.1 Client Access

## Outcome

Provide customer-scoped portal principals, membership administration, invitations
and immediate revocation enforcement behind disabled-by-default organization
flags.

## Inputs and dependencies

- Source decisions: 15, 17, 28-43, 59, 84, 88-89.
- Predecessor: `15.0-contract-freeze`.
- Inputs: frozen portal contract, identity policy and Phase 05 authorization.

## Ownership and compatibility

- Owns: portal principal/authorization adapters, portal feature flags, portal
  membership controllers and their tests.
- Prohibited: Keycloak provider configuration; canonical customer, invoice,
  payment, support, file and audit schemas.
- Output: client member/admin roles, project grants, invite/remove audit events,
  fresh-session guard and revocation checks.
- Impact: new `/api/v1/portal` authorization boundary only; no canonical DTOs.

## Actions and verification

1. Resolve every portal request by organization and customer/project grant.
2. Permit client admins to manage only their own customer membership.
3. Require fresh sensitive sessions for financial, contract and signed-link
   actions.
4. Test cross-organization identifiers, cross-customer identifiers, role
   escalation, revoked sessions and new signed-link denial.
- Evidence: `docs/evidence/phase-15/15.1-access/`.
- Security: return indistinguishable denial responses without existence leaks.
- Capacity/cost: bound membership lookups and record query measurements.
- Rollback: disable `portal-access`; revoke portal sessions.
- Merge order: after `15.0`; contract version must match the frozen version.
