# 16.6 — releases and authorized downloads

## Outcome

Publish eligible product releases with checksums, mandatory signatures,
platform requirements, support status and audited, time-bounded downloads.

## Inputs and ownership

- Sources: decisions 029, 031, 041, 051, 079, 085 and frozen `16.0–16.4`.
- Owns: release metadata, entitlement authorization, download-audit APIs and
  account UI.
- Prohibits: permanent public URLs, storage provider activation and signing keys.

## Actions and compatibility

1. Bind release eligibility to an entitlement snapshot and license policy.
2. Store public verification metadata only; sign artifacts outside application
   data and rotate keys through the `16.4` contract.
3. Issue bounded download capabilities only after authorization and audit.

## Verification and evidence

- Test authorization, revoked access, signature/checksum verification, audit
  completeness and supported-version rollback.
- Evidence: `docs/evidence/phase-16/16.6-releases-downloads/`.
- Capacity/cost: no large-binary activation without `16.8` headroom evidence.
- Rollback: disable downloads; retain release metadata and staff recovery path.
- Merge: after `16.4`; requires separately verified private storage.
