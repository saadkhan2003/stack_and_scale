# 16.2 — subscription lifecycle

## Outcome

Implement an audited pending/trial/active/past-due/suspended/cancelled/expired/
terminated lifecycle with time-bounded authorized overrides.

## Inputs and ownership

- Sources: decisions 012, 013, 040, 043, 045, 079 and frozen `16.0–16.1`.
- Owns: subscription schema, transition service, event DTOs and tests.
- Prohibits: invoice/payment status mutation, entitlement resolver and license
  activation logic.

## Actions and compatibility

1. Store effective timestamps, reason, actor and idempotency key per event.
2. Reject illegal/replayed transitions and expired manual overrides.
3. Expose a versioned read model; do not infer entitlement from payment state.

## Verification and evidence

- Exercise every legal/illegal transition, duplicate event and override expiry.
- Evidence: `docs/evidence/phase-16/16.2-subscriptions/`.
- Capacity/cost: append-only events with indexed current state; $0 change.
- Rollback: disable automated transitions; preserve staff-assisted operations.
- Merge: after `16.1`; freezes subscription event semantics.
