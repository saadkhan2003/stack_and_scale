# Step 13.9 - Operational Reports

Reports are aggregate-only. JSON reads remain synchronous. CSV exports are
queued as tenant-owned PostgreSQL jobs and rendered by the existing worker;
the API returns a status response until an authorized download is available.
The API accepts `funnel`, `response-time`, `workload`, `conversion`, or
`activity`, optional ISO timestamps, and an IANA timezone. Defaults are the
previous 30 days in UTC; windows must be positive and no longer than 92 days.
CSV jobs require `report:export`; JSON requires `report:read`.

Formulas:

- Funnel: current lead count grouped by stage for leads created in the window;
  stage history is not available in the current schema.
- Response time: average minutes from lead creation to first lead activity;
  leads without an activity are excluded.
- Workload: tasks created in range grouped by assignee; `completed_at IS NULL`
  is open.
- Conversion: won leads / all leads by source x 100.
- Activity: lead activity count grouped by activity type.

Report results contain no lead names, emails, messages, or attribution. Every
read, queue, completion, failure, and download event is audit recorded. Jobs
are tenant-filtered, claimed with row locking, and retained for at most 24
hours before the worker removes their CSV body and terminal record.
