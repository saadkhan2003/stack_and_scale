# Step 13.2 — Operational Dashboard

## Outcome

Expose bounded, actionable lead and follow-up queues to authorized staff.

## Predecessors

13.1

## Owned files

- `apps/web/app/staff/**`
- `apps/web/src/staff-*.tsx`
- dashboard API proxy and tests

## Prohibited writes

- Authorization matrix and CRM schema without a separate contract review.

## Actions

- Define new leads, overdue tasks and upcoming demos from existing records.
- Link each metric to a staff action and document timezone behavior.
- Keep query limits bounded and avoid exposing cross-organization data.

## Verification

Run web/API tests, role-matrix tests, accessibility checks and bounded list
performance measurements against production-like records.
