## Metric definitions

- **New leads:** records currently in the `new` stage, newest first, maximum 50.
- **Overdue follow-ups:** incomplete tasks with a non-null `due_at` earlier than database `now()`, oldest due first, maximum 50.
- **Upcoming demos:** confirmed bookings from database `now()` through the next 14 days, ordered by `starts_at`, maximum 50. The stored booking `timezone` is returned and displayed as the source timezone.
- **Pipeline stages:** grouped counts for existing lead stages, ordered `new`, `qualified`, `proposal`, `won`, `lost`.
- **Pending approvals:** approval requests with `decision = 'pending'` and `expires_at > now()`, ordered by expiry, maximum 50.
- **Unresolved support items:** support records with status `open`, `in_progress`, or `pending_customer`; `resolved` and `closed` are excluded, maximum 50 and oldest update first with critical/high severity first.

All dashboard queries use the organization ID resolved by `CrmAccessService`, including leads, tasks, demos, stage counts, support items and approvals. PostgreSQL time controls queue boundaries. Migration `0008_phase_13_dashboard_approval_lifecycle.sql` adds only the support read primitive and approval lifecycle timestamps.
