# Phase 13.2 Operational Dashboard Evidence

## Delivered

- Added `GET /api/v1/crm/summary`, protected by `CrmAccessService` with the existing `crm:read` permission.
- Added the server-side staff proxy at `/api/staff/crm/summary`.
- Replaced the staff dashboard placeholder with actionable cards for new leads, overdue follow-ups, upcoming demos and lead stage counts. Every card links to the protected lead inbox.

## Metric definitions

- **New leads:** records currently in the `new` stage, newest first, maximum 50.
- **Overdue follow-ups:** incomplete tasks with a non-null `due_at` earlier than database `now()`, oldest due first, maximum 50.
- **Upcoming demos:** confirmed bookings from database `now()` through the next 14 days, ordered by `starts_at`, maximum 50. The stored booking `timezone` is returned and displayed as the source timezone.
- **Pipeline stages:** grouped counts for existing lead stages, ordered `new`, `qualified`, `proposal`, `won`, `lost`.

The dashboard uses PostgreSQL time for queue boundaries and does not introduce a migration or change the authorization contract. CRM data remains within the existing configured CRM organization scope enforced by `CrmAccessService`.
