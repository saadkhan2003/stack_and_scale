# Phase 14.7-14.9 Evidence

## Boundaries

- Private file metadata, versions, ownership, retention, quota accounting, scan status and append-only download audits are tenant-scoped in migration `0015`.
- `PrivateObjectStorage.createSignedAccess` is the only access URL operation and enforces a maximum 15-minute lifetime. The API issues five-minute access after authorization and a clean scan state.
- The default scan implementation is an explicit pending hook. No malware vendor is enabled or claimed.
- Provisioning requests use organization idempotency keys, durable ordered steps, owner/failure/retry fields, and approval requests for privileged or high-cost steps. Execution remains provider-neutral.
- Approved communication templates are versioned. Preference checks map commercial events to existing notification categories, and outbox delivery exposes queued, delivered, failed, and resend state.

## Verification scenarios

- Tenant predicates are present on file, provisioning, template, communication, and audit queries.
- Quota rejection happens before object metadata is committed.
- Signed access is denied for pending or quarantined scans.
- Repeating a provisioning idempotency key returns the existing request.
- Privileged provisioning starts blocked with a separation-of-duties approval request.
- Disabled communication preferences produce `not_requested`; resend creates a new outbox event only for failed or delivered records.
