# Phase 14.3 Evidence: Contracts and E-Sign Boundary

## Implemented

- `0012_phase_14_3_contracts_esign.sql` adds tenant-scoped contract templates,
  template versions, contract records, signer identity evidence, signing
  attempts, provider callback receipts, and signed-artifact metadata.
- `packages/contracts/src/contracts.ts` defines immutable content hashes,
  proposal-version binding validation, an `ESignProviderAdapter` interface,
  constant-time HMAC callback verification, retry backoff, and retention-safe
  artifact metadata.
- `apps/api/src/contracts/contract.service.ts` and controllers provide template
  versioning, contract creation bound to an issued proposal version, signer
  capture, gated signing, callback idempotency, retryable failure state, and
  controlled uploaded signed-document fallback.

## Provider gate

No real provider is integrated or enabled. Signing requires
`ESIGN_PROVIDER_ENABLED=true`, `ESIGN_PROVIDER_APPROVED=true`, a registered
adapter, and `ESIGN_PROVIDER_CALLBACK_SECRET`. The approval flag is an explicit
legal/provider/cost gate, not evidence that a signature is qualified. The
uploaded fallback is retained as `uploaded_signed_fallback` and returns
`completionSubstitute: false`.

## Verification

Focused contract and service tests cover exact template/proposal version
binding, callback tampering and HMAC authenticity, duplicate callback handling,
retryable provider failures with backoff, and artifact checksum/path/retention
metadata. Provider legal suitability, jurisdiction, data location, and any
qualified-signature claim remain pending external approval.
