# Phase 15.6 — assurance and controlled rollout

## Release controls implemented

- Every portal area is feature flagged per client organization and defaults to
  disabled in the database migrations.
- Client administrators can only manage members of their own client
  organization. A person must have an existing identity record (created by a
  first sign-in) before an administrator can add them. Add and revoke actions
  are recorded in an append-only portal membership-event table; an
  administrator cannot revoke their own access through this endpoint.
- The browser portal exposes this member-management flow only to a resolved
  `client_admin`. Its Next relay accepts only the exact member list, grant and
  revoke paths; it cannot be used as a general-purpose API proxy.
- Portal responses use client-safe projection tables and bounded query limits.
- Browser mutations are relayed through explicitly allow-listed Next routes;
  arbitrary API paths are not exposed by the browser relay.
- Sensitive browser pages are dynamic and send `no-store` responses through
  their API relays. The portal page is marked `noindex`.
- Project, review, commercial, files, support and activity boundaries are
  independently enforced in the API, rather than relying on a web-page check.

## Required release evidence (not yet available)

1. Run the portal API integration suite against PostgreSQL from CI or the
   development host.
2. Create a non-production client account and feature-flagged client
   organization; browser-test authorized access, cross-client denial, ticket
   creation, review decision and notification preference changes.
3. Deploy the committed Phase 15 image through the immutable workflow, then
   repeat the browser smoke test against the production portal only with an
   approved real client account.
4. Record host capacity measurements after rollout and a portal flag rollback
   drill. Do not use production customer data in evidence.
5. Do not expose a deliverable download until Phase 14's approved private
   object storage, malware scan and short-lived signed URL capability are
   configured and separately verified.
